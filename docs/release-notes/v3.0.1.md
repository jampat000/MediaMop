# Weir v3.0.1

Date: 2026-09-18

This patch release stops Weir processing the same file twice when a media manager's hand-off and Weir's own library scan both find it.

## Fixes And Stability

- **One pass per file.** If a library scan had already queued a file and Sonarr or Radarr then handed the same file over, Weir queued it a second time and ran ffmpeg on it twice. The hand-off now takes over the job that is already queued or running, so the file is processed once and the hand-off's status and callback follow that job. A scan's automatic retry of a failed file, and a hand-off arriving in the middle of a scan, are covered by the same fix.
- **Plain message when Weir can't be reached.** If Weir's server stops while a page is open, actions now say "Can't reach Weir. Check it's still running, then try again." instead of the browser's raw "Failed to fetch".
- **Safer log lines.** Request details written to Weir's log have control characters escaped, so a crafted request can no longer add fake lines to the log.

## Upgrade Notes

- No configuration or database change. Your settings, libraries and history carry over.
- Windows users on 3.0.0 can upgrade from **Settings -> Upgrade** or **Check for updates** in the tray, or install `Weir-win-Setup.exe` over the top.
- Docker users: `docker compose pull && docker compose up -d`.
- Coming from MediaMop 2.x, or from anything older than 3.0.0? Read the [3.0.0 notes](https://github.com/jampat000/Weir/releases/tag/v3.0.0) first — that release changed the port, paths and API.
