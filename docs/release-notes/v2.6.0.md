# MediaMop v2.6.0

Date: 2026-09-01

This release makes MediaMop safer to operate, clearer to configure, and ready for a more reliable Windows and Docker release path.

## What Changed

- The Dashboard now tells you what needs attention and links directly to the next action.
- Activity is a compact, grouped timeline with consistent counts, filters, and live updates.
- Refiner and Pruner setup states explain what is configured, what is unavailable, and what to do next.
- Settings is organized into task-based sections with deep links, browser history, security posture, and session controls.
- The desktop shell now supports a collapsible sidebar, responsive mobile navigation, theme control, and clearer status styling.

## Fixes And Stability

- Refiner failures now retain useful diagnostics, retry with backoff, and quarantine repeated failures as one visible incident.
- Windows log retention works while the active service log is open.
- HTTPS cookie, proxy, readiness, response-header, compression, and outbound-connection behavior is hardened.
- Notification deletion, session revocation, and other state-changing actions enforce the browser security contract.
- Production assets use optimized WebP branding, immutable caching, bundle budgets, and no source maps.
- Python dependencies are hash-locked, GitHub Actions are immutably pinned, and documentation checks run in CI.

## Upgrade Notes

- If you are upgrading from an older Windows install that predates the updater service, run `MediaMopSetup.exe` once as administrator.
- After that one-time bootstrap, future upgrades can be started from **Settings -> Upgrade**.
- Existing databases and settings are migrated automatically; the session-label migration is additive.
- Docker users should pull `ghcr.io/jampat000/mediamop:2.6.0` or `:latest` and keep the existing `/data/mediamop` volume.
