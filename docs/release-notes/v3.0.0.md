# Weir v3.0.0

Date: 2026-09-18

This is a major release: MediaMop is now Weir, the word Refiner is gone from the product, the server has been rewritten on .NET, and the API routes and database tables have been renamed to match — so read the breaking changes below before you upgrade.

## Breaking Changes

Most of this is handled for you. The one item that needs your attention is the first.

- **API routes have moved.** `/api/v1/refiner/...` is now `/api/v1/processing/...`. The old paths are gone; they are not redirected. **If you have a script, a dashboard, a webhook or any other tool calling Weir's API, you have to update it.** Two smaller route changes go with it: `/api/v1/suite/pause` is now `/api/v1/pause`, and `GET /api/v1/dashboard/status` has been removed.
- **Database tables have been renamed, automatically.** The `refiner_` prefix is gone, because the database is Weir's: `refiner_libraries` becomes `libraries`, `refiner_jobs` becomes `jobs`, `refiner_files` becomes `files`, and the same for the file logs, rule sets, library manager links and operator settings. Job kinds and activity event names lose the prefix too. A migration does all of this on first start, including the rows you already have. **If you use Weir through its own screens, there is nothing for you to do.** Only direct SQL against the database needs changing.
- **The product is called Weir everywhere, and there is no upgrade path from a MediaMop install.** The Docker image is `ghcr.io/jampat000/weir`, the data volume is `/data/weir`, the database file is `weir.sqlite3`, environment variables are `WEIR_*`, and the Windows installer is `Weir-win-Setup.exe`. There are no `MEDIAMOP_*` fallbacks and nothing reads the old paths. A MediaMop installation is not migrated — Weir installs as a new application, with a new configuration.
- **Pruner has been removed.** Its job now lives in Deluno. Its pages, settings, notifications and activity types are gone, its tables are dropped by a migration, and the Jellyfin, Emby and Plex credentials that only Pruner used have gone with it. Pruner sections in an older configuration backup are ignored on restore rather than failing it.
- **The Dashboard has been removed.** **Home** at `/` is the main screen and shows warnings when something is wrong. `/dashboard` is gone rather than redirected — an old bookmark gets the not-found page.
- **Every suite API handler answers on one address now.** The configuration bundle used to be reachable at three URLs, the snapshot list and download at two each, and the update check at two, because the .NET port kept the Python spellings alongside the new ones. The aliases are gone: `GET`/`PUT /api/v1/system/suite-configuration-bundle`, `GET /api/v1/system/suite-configuration-backups` and its `/download`, `GET`/`PUT /api/v1/suite/settings/configuration-bundle` and `GET /api/v1/suite/settings/update-status` all return not-found. Use `/api/v1/suite/configuration-bundle`, `/api/v1/suite/configuration-backups` and `/api/v1/suite/update-status`.
- **`application_logs_enabled` has been removed from the settings API.** It was accepted and then discarded — setting it never did anything. Sending it now is ignored along with any other unknown key, rather than being quietly accepted as if it mattered.
- **Three environment variables have been removed:** `WEIR_SUBBER_WEBHOOK_SECRET` (use `WEIR_MEDIA_MANAGER_WEBHOOK_SECRET`), the `WEIR_PROCESSING_WORK_TEMP_STALE_SWEEP_*` spelling of the stale-sweep schedule, and `WEIR_PROCESSING_REMUX_MEDIA_ROOT`, which was read from the environment and then never used for anything. Setting one now does nothing instead of appearing to work.
- **Configuration backups from before 3.0.0 cannot be restored.** Only format version 4 — what this release exports — is accepted. Export a fresh bundle after upgrading.
- **The two old default work folders are treated as ordinary custom paths.** A library whose work folder is literally `C:\ProgramData\Media\processing-movie-work` or `C:\ProgramData\Weir\processing-tv-work` used to be quietly redirected to the default under `WEIR_HOME`, and created if missing. It is now used exactly as stored, and the run is refused if the folder does not exist. **A library with no work folder set is unaffected** and still uses the default. If you have one of those paths saved, either clear the field or make sure the folder exists.

## What Changed

- **Weir's server is a new program.** The Python backend has been deleted and replaced by a .NET 10 build. Same port, same volume, same data paths, same health check, and Docker images for both `linux/amd64` and `linux/arm64`. The Windows package bundles the .NET server and ffmpeg, and the tray app supervises it as before. One packaging bug went with the rewrite: the packaged server never looked in its own bundled ffmpeg folder.
- **A new theme, Tailrace.** Cool slate surfaces with a teal-cyan accent, chosen to sit apart from the blues and oranges of the tools Weir works with. Text, links and focus rings pass contrast in both dark and light. There is a new mark to go with it: three streams falling over a wall, traced from the drawing that was accepted rather than redrawn by eye. A second, simpler two-stream drawing exists only for the 16px frame inside the favicon and the Windows tray icon, where three bands fuse into a smear; at 24px and above — every other icon size, the SVG favicon and the mark in the sidebar — you are looking at the three-stream mark.
- **The inside of every page has been redesigned; the menus around it have not.** The sidebar, the top bar, the page header and the tab row are exactly as they were — they were finished, and they were left alone on purpose. Everything inside them has been rebuilt to one written-down language, page by page, from the first-run wizard to Settings. The sign-in and not-found screens were already this plain and are unchanged. Nothing an integration depends on moved: this is how the pages look, not what they do.
- **Three screens now lead with a status band.** **Home**, **Processing -> Overview** and **Processing -> Files** each open with one full-width band whose segments are as wide as the number each one carries, so where your files are sitting is the first thing you see. Every segment is a control — click one and you land on the file list filtered to exactly that state. The band never quietly drops a state it does not draw: it counts those too and says so in the line underneath.
- **Where a band could not be drawn honestly, there is none.** Activity has no band because its outcome counts cannot be gathered often enough to stay live without making every page in a run refetch, and Settings has no band because it has no "now". The same restraint applies to the big numbers: a page only leads with one where there is a real number to lead with.
- **Most cards and panels are gone.** Instead of boxes inside boxes, a section is a heading, a hairline and its content, and tables have lost their frames. Below 760px a table folds into labelled rows, so the Library file list's nine columns are readable on a phone for the first time — the trade is that the sort controls and the select-all box, which live in the header row, are not there at that width.
- **Settings lost its boxes too, except where one is doing a job.** General is now a single column of headed groups, each with its **Save** directly beneath its own rule, so it is always clear which form a button writes. Each media manager connection still sits in a frame, because it carries three actions and a one-time secret, and the frame is what says which **Remove** belongs to which connection.
- **A real Library view.** The tab that used to be a bare list is now **Library**, with its own sub-navigation: **Overview** (file and size totals, how many match your rules, would change, or cannot be processed, estimated space saved, and breakdowns by video codec, resolution, audio codec and channels, audio language and subtitle language), **Files** (a sortable, paged table you can narrow with facet filters, with multi-select cleaning and a per-file rules preview), **Codecs** and **Languages** (the same breakdowns as sortable tables), and **Problems** (groups with plain advice, plus the titles your media manager could download again). A migration fills the new breakdown data in from each file's cached probe results — nothing is re-probed, and anything unknown reads "unknown".
- **mkvmerge now ships with Weir and writes Matroska by default.** ffmpeg is still bundled and still writes everything else. Each library has a writer setting: `best`, the default, means mkvmerge for `.mkv` and ffmpeg for every other container; `ffmpeg` means ffmpeg writes everything, which is what every earlier version did. On Matroska, mkvmerge keeps attachments and disposition flags, and drops stale per-track statistics tags. The screen for choosing per library follows in a later release; the default applies to existing libraries as well as new ones.
- **A failed write is rewritten by ffmpeg, so the new writer cannot leave you worse off.** If mkvmerge fails to run, or its output fails Weir's own output validation, ffmpeg rewrites the file and it is validated again. A cancelled job stays cancelled rather than quietly starting a second write. Files where your rules keep embedded cover art are written by ffmpeg, as they were before.
- **What was tested through both writers, and what was not.** Dolby Vision profile 7, TrueHD Atmos and DTS-HD MA all come through mkvmerge and ffmpeg byte-identically on real UHD remuxes. **PGS subtitles have not been verified** — no sample was obtainable — so treat PGS through mkvmerge as untested.
- **Libraries know about your media manager.** Files in a library are matched to their Sonarr or Radarr titles, so the re-download warnings and the "Download again" action work on them. Libraries can be discovered from a connected manager, imported, checked for drift and unlinked.
- **Watched folders are watched, not polled.** Each enabled library gets a filesystem watcher, debounced, falling back to a full rescan if it is overwhelmed, and readiness reports what the watcher is actually doing.
- **More of the rules are editable.** Hearing-impaired subtitle removal, language variants, per-language caps on audio and subtitle tracks, track name templates with a live preview, clearing video track names, and removing chapters.
- **Home tells each file's story in plain language** — what state it is in, why, and with live per-file progress — and a read-only Direct Play badge shows whether a file will play directly on the devices you own.
- **Activity is a history page.** Filter it, group it by run, export it, keep it for a stated time and prune it. Every entry says why it happened and how it went.
- **`Weir recover`** resets a password, reactivates an account, revokes sessions and records the fact in Activity, for when you are locked out of your own install.
- **Output ownership on Linux.** `WEIR_CHOWN_OUTPUT`, `WEIR_FILE_MODE_OUTPUT` and `WEIR_DIR_MODE_OUTPUT` are applied when Weir publishes a file. They are ignored on Windows, with a warning.

## Fixes And Stability

- **The migration engine could delete rows when a migration rebuilt a table.** Rebuilding a table in SQLite means creating the new one, copying the rows across and dropping the old one — and dropping it fires `ON DELETE CASCADE` on everything that references it, taking the children with it, and their children after that. Weir tried to hold this off with `defer_foreign_keys`, but that only defers *violations*; it does not stop a cascade, and `PRAGMA foreign_keys` is a no-op inside a transaction, which is where it was being set. Foreign keys are now turned off before the transaction is opened and checked with `PRAGMA foreign_key_check` before it commits. This was present in every release that has shipped, and it is the most serious thing fixed here.
- **Restoring a configuration backup from a file was broken.** Settings refused any bundle whose format version was not 1, while the server has written version 4 since the configuration rework — so every genuine export was rejected before it was even sent. The version is the server's to check, and the screen no longer second-guesses it. If you concluded your backups were corrupt, they were not.
- **A file that made ffprobe print a warning failed its own remux, every time.** Weir fails a remux when the output carries a warning the source did not. Before comparing, it normalises the pointer addresses in ffmpeg's messages — but ffmpeg prints those addresses bare, with no `0x`, so they were never matched and every warning on a correct output looked new. Any such file was picked up, rejected and retried forever. A font attachment is the easy way to hit it, which means most anime could never be processed. Nothing was lost — Weir hands the original back rather than stranding a file — but nothing could be done with those files either. Fixed, with tests written from real captured ffmpeg output rather than invented shapes.
- **Weir never strands a file.** If processing gives up, the original is handed back. A release Weir cannot process is rejected with a reason instead of being retried blindly, and a failed file can be retried or requeued from the Files screen.
- **Folder hand-offs report states a media manager accepts**, and a manager can ask about a hand-off and cancel it.
- **A failed job now writes one plain Activity entry**, with retry wording that matches what actually happens, instead of several confusing ones.
- **The last retry gap** from the job-queue rework is closed, and library mode and rule options now have proper database columns rather than living in a settings row.
- **On a phone, the hidden menu is now really hidden.** Below 920px the sidebar slides off the side of the screen — but it stayed in the tab order, so a keyboard or screen-reader user tabbed through all four links and could reach **Sign out** without ever seeing the menu, before reaching the button that opens it. It is now out of the tab order and the accessibility tree while it is closed, and the slide-out is unchanged. Two smaller things went with it: the sidebar is announced as "Weir" rather than "Product", and the line under the wordmark says what Weir actually does now — "Cleans new downloads, and files already in your library" — instead of describing only half of it.
- **Remove asks first.** **Remove** on a media manager connection, and on a notification channel, deleted it on the first click with nothing asked and nothing to undo. Both now open a confirmation that names the item it is about to remove, opens with **Cancel** focused so Enter keeps the thing, and closes on Escape. What Remove does once you confirm is unchanged.
- **A burst of hand-offs could fail after thirty seconds.** When several downloads arrived at once, a hand-off that read the database before writing to it could find another hand-off had written first. SQLite then refuses the write outright rather than waiting, so the request retried until it timed out and failed. With sixteen hand-offs arriving together, 43 of 320 used to fail this way; now none do, and they finish in milliseconds instead of half a minute. The fix covers every part of Weir that reads then writes, not only hand-offs.
- **Four job actions could hang for thirty seconds and then fail.** Cancelling a queued job, recovering a job that failed to finalise, moving a file to the top of the queue and requeuing a file each held the database's single write lock for the request and then waited for that same lock a second time, so they stalled for the full timeout and answered with an error. It only happened when the request also refreshed your sign-in, which is why it looked random rather than broken. Fixed at all four.
- **Narrow desktop windows stopped cutting the right-hand edge off.** From the width where the sidebar becomes a drawer up to about 1100px — and up to about 1300px on the Jobs and Library file tables — the main column was wider than the window and the excess was clipped rather than scrolled, so the theme toggle, the end of the tab row and the right-hand columns of tables were simply missing, with no scrollbar to hint at it. Processing's tabs and Settings were affected; Home and Activity were not. It was there before the redesign, not caused by it.
- **The screen you get when a page fails now looks like Weir.** It used eight class names that nothing in the app styled, so its heading, its explanation and its **Reload Weir** button all rendered as the same plain text — and it rebuilt the app's sidebar inside the failure, which pushed the message itself below the fold and drew a second sidebar beside the real one when you were signed in. It is now the same shape as the not-found page, focus moves to the message when it appears, and it offers a link back to the start.
- **The loading placeholder draws something.** While a page's code loads, the placeholder sidebar beside "Loading Weir" was a blank rectangle: the marks it was meant to show were styled by class names that did not exist. They are there now, and they stop moving if you have asked for reduced motion.
- **Sign-in hardening:** case-insensitive usernames, a way to change yours, a per-request Secure cookie, and two lockout fixes. The minimum password length is 8 everywhere, pinned by a test.
- **Dependency updates** across the server, the web app, the tray and the test tooling, including three major test-infrastructure versions verified locally before merge.

## Upgrade Notes

- **Most people need to do nothing.** The table renames, the Pruner cleanup and the new library breakdown data are all applied by migrations when Weir first starts.
- **If anything of yours calls Weir's API, change `/api/v1/refiner/...` to `/api/v1/processing/...` before you upgrade.** Also `/api/v1/suite/pause` to `/api/v1/pause`. `GET /api/v1/dashboard/status` no longer exists.
- **Coming from MediaMop 2.x?** There is no in-place upgrade. The application name, install location, data path, database file, environment variables and Docker image have all changed, and nothing reads the old ones. Install Weir fresh and configure it.
- Windows users can install the release with `Weir-win-Setup.exe`; it installs per user under `%LocalAppData%\Weir` and needs no administrator.
- After that one-time bootstrap, future upgrades can be started from **Settings -> Upgrade**, or from **Check for updates** in the tray.
- Docker users should pull the new image name and use a `/data/weir` volume. Upgrade with `docker compose pull && docker compose up -d`.
- **Databases from this release cannot be opened by an older version.** Take a copy of your data volume before upgrading if you want a way back.
